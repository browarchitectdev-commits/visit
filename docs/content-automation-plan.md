# План автоматизации публикации контента через бота (Telegram/WhatsApp)

## 1. Цель
Сделать систему, в которой администратор отправляет данные боту, а контент автоматически добавляется в проект с TinaCMS (Git-based) и публикуется после деплоя на Vercel.

Поддерживаемые разделы:
- Соцсети
- Услуги
- Мастера
- Галерея

## 2. Что именно должно работать

### 2.1 Базовый сценарий
1. Админ пишет боту.
2. Выбирает тип контента: соцсети / услуги / мастера / галерея.
3. Бот пошагово запрашивает поля.
4. Бэкенд валидирует данные.
5. Создается/обновляется JSON-файл в `src/content/...`.
6. При наличии медиа — файл сохраняется в `public/uploads/...`.
7. Сервис делает commit в GitHub.
8. Vercel запускает деплой и публикует изменения.

### 2.2 Соцсети без ручного выбора платформы
Платформа определяется автоматически по ссылке:
- `instagram.com` -> `instagram`
- `tiktok.com` -> `tiktok`
- `facebook.com` -> `facebook`

Если платформа не распознана — бот просит отправить корректную ссылку.

## 3. Архитектура решения

### 3.1 Компоненты
- Telegram Bot (входной канал команд)
- Webhook/API Route на Vercel (`src/pages/api/bot/webhook.ts`)
- Валидатор + маппер в формат Content Collections
- Модуль записи контента в репозиторий
- GitHub API (commit изменений)

### 3.2 Поток данных
1. Telegram отправляет update в webhook.
2. Webhook проверяет `adminId` (whitelist).
3. Состояние диалога хранится по `chatId` (KV/in-memory/простая JSON-таблица).
4. После завершения формы данные валидируются через Zod.
5. Генерируется slug/filename.
6. Создается commit в ветку `main` (или в отдельную `content-bot`).
7. Vercel пересобирает сайт.

## 4. Безопасность
- Принимать команды только от белого списка Telegram user IDs.
- Токены хранить только в переменных окружения.
- Не логировать токены и приватные данные.
- Проверять URL, MIME-тип, размер медиа.
- Ограничить rate limit на webhook.

## 5. Данные и валидация по разделам

### 5.1 Соцсети
Минимум:
- `postUrl` (обязательно)
- `title` (опционально)
- `caption` (опционально)
- `isActive` (по умолчанию `true`)
- `order` (по умолчанию авто)

Автоопределение `platform` из `postUrl`.

### 5.2 Услуги
Минимум:
- `name`
- `price`
- `duration`
- `description`
- `image`

### 5.3 Мастера
Минимум:
- `name`
- `position`
- `experience`
- `bio`
- `photo`

### 5.4 Галерея
Минимум:
- `title`
- `category`
- `description`
- `imageBefore`
- `imageAfter`

## 6. UX бота (MVP)

### 6.1 Команды
- `/start` — приветствие
- `/new` — начать создание контента
- `/cancel` — отменить текущую сессию
- `/publish` — мгновенная публикация (если включено)
- `/draft` — сохранить как черновик

### 6.2 Сценарий /new
1. Бот показывает кнопки: Соцсети / Услуги / Мастера / Галерея.
2. Бот задает нужные поля по выбранному типу.
3. После заполнения показывает предпросмотр.
4. Кнопки: Подтвердить / Исправить / Отмена.

## 7. Публикация: сразу или через модерацию
Рекомендуемый режим:
- По умолчанию сохранять как draft/pending.
- Отдельная команда на публикацию.

Альтернатива:
- Автопубликация сразу после подтверждения.

## 8. Стоимость и лимиты

### 8.1 Можно сделать почти бесплатно (MVP)
- Telegram Bot API: бесплатно
- GitHub API: бесплатно в обычных лимитах
- Vercel Free: подходит для MVP, но есть лимиты
- Tina в Git-режиме: можно без платного Cloud-функционала

### 8.2 Что может стать платным
- Высокая нагрузка на Vercel (много билдов/запросов)
- WhatsApp Business API (обычно платный)
- Внешнее хранилище медиа при росте объема

## 9. Telegram vs WhatsApp

### Telegram (рекомендуется старт)
Плюсы:
- Быстро и бесплатно
- Простая интеграция webhook
- Удобные inline-кнопки

Минусы:
- Нужен Telegram у админов

### WhatsApp
Плюсы:
- Привычный канал общения

Минусы:
- Сложнее интеграция
- Часто платно
- Больше бюрократии (Meta Business)

## 10. Этапы реализации

### Этап 1 (MVP: соцсети)
- Webhook endpoint
- Авторизация по admin IDs
- Автоопределение соцсети по ссылке
- Создание JSON в `src/content/social/`
- Commit в GitHub

### Этап 2 (услуги/мастера/галерея)
- Пошаговые формы для каждого типа
- Загрузка медиа в `public/uploads/`
- Привязка путей к полям коллекций

### Этап 3 (качество и контроль)
- Режим draft/pending + approve
- Логи/аудит
- Повторная отправка при ошибках
- Ограничения на размеры файлов

## 11. Переменные окружения
Пример:
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_WEBHOOK_SECRET`
- `TELEGRAM_ADMIN_IDS` (через запятую)
- `GITHUB_TOKEN`
- `GITHUB_OWNER`
- `GITHUB_REPO`
- `GITHUB_BRANCH` (например `main`)

## 12. Технические риски и как снизить
- Невалидный контент -> строгая Zod-валидация перед commit.
- Конфликты commit -> ретраи + чтение последнего SHA перед записью.
- Спам в боте -> whitelist + rate limit.
- Ошибка медиа -> проверка формата и размера до сохранения.

## 13. Definition of Done (MVP)
MVP считается завершенным, если:
1. Админ может создать запись соцсети через Telegram.
2. Платформа определяется автоматически по ссылке.
3. Запись попадает в `src/content/social/*.json` с корректной схемой.
4. Изменения коммитятся в GitHub автоматически.
5. После деплоя запись видна на сайте.

## 14. Рекомендуемый старт
Начать с Telegram + раздел Соцсети, затем расширять на остальные коллекции.
Это минимальный риск, минимальная стоимость и быстрый результат.
